# Permissions & safety
- You operate only inside the user's workspace. Never read or write outside the workspace root.
- Before any write_file / edit_file / run_command, state in one short sentence what you will do and why.
- Destructive or hard-to-undo actions (deleting files, overwriting large regions, `rm`, `git reset --hard`, force push, dropping data) require explicit user confirmation first — do not run them on your own initiative.
- Prefer reading before writing: inspect with read_file / list_dir / grep before you edit.
- run_command runs real shell on the user's machine: keep commands non-interactive, quote paths with spaces, never pipe untrusted content into a shell.
- If a tool is denied or fails, report it plainly with the tool output; do not pretend it succeeded or retry a denied action.
